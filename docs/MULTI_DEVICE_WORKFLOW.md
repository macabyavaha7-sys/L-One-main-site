# L-One 主站多设备协作流程

GitHub 是 A、B 设备之间唯一的版本中心。当前默认采用串行接力：同一时间只允许
一台设备执行生产任务。不得使用压缩包、云盘同步或旧项目目录覆盖 Git 工作区。

## A 设备结束任务

1. 拉取远程最新状态并完成授权范围内的修改。
2. 运行完整的任务相关测试，检查页面、控制台和 API。
3. 检查 diff，仅精确暂存本轮文件。
4. 更新 `docs/CURRENT_HANDOFF.md`，记录测试、部署和已知问题。
5. 创建规范 commit 并推送 GitHub。
6. 核对 GitHub 与 EdgeOne 的 commit 和部署结果。
7. 记录最终 commit ID，保持工作区干净并停止继续修改。

## B 设备接手任务

1. 检查工作区；存在不明变更时停止并报告。
2. `git fetch --all --prune`，然后 `git pull --ff-only origin main`。
3. 阅读全部协作、状态和任务边界文档。
4. 查看最近 10 次提交并记录接手基线 commit。
5. 运行当前版本的审计、测试和关键页面检查。
6. 声明任务编号及精确编辑范围后才开始修改。

## 设备切换门槛

只有同时满足以下条件才允许交接：

- 上一设备已完成测试、commit 和 push；
- GitHub 已显示交接 commit；
- `docs/CURRENT_HANDOFF.md` 已更新；
- EdgeOne 状态已记录为成功、失败或明确的未验证；
- 下一设备已拉取远程最新版本；
- 没有未提交修改、未推送 commit、未处理冲突或未知部署状态。

## 并行任务

确需并行时：

1. 每个任务使用独立分支，名称必须包含设备代号和任务编号。
2. 两台设备不得同时修改 `main`，并尽量避免编辑同一文件。
3. 合并前检查冲突并重新运行测试。
4. 只有最终合并到 `main` 后才触发正式部署。

## 固定任务节奏

```text
读取规则与交接
→ 检查工作区
→ fetch + ff-only pull
→ 记录基线
→ 声明编辑范围
→ 修改与测试
→ 检查 diff
→ 精确暂存
→ 更新交接
→ commit + push
→ 核对 GitHub、EdgeOne 和正式域名
```

禁止持续监听文件并自动推送；保存文件不等于允许提交或发布。
