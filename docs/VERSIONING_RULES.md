# L-One 主站任务、分支、提交与版本规则

## 任务编号

格式：`设备代号-YYYYMMDD-当日序号`。

示例：`B-20260728-01`、`A-20260728-02`。首次协作初始化使用
`B-20260728-00`。

## 分支名称

- 日常任务：`work/<设备>-<日期>-<序号>-<任务简称>`
- 紧急修复：`hotfix/<设备>-<日期>-<任务简称>`

示例：

```text
work/B-20260728-01-home-copy
hotfix/A-20260728-admin-login
```

当前串行接力模式允许经完整检查后从 `main` 完成极小、明确的维护提交；并行工作、
较高风险变更和需要审核的任务必须使用独立分支。只有 `main` 触发正式部署。

## Commit 信息

格式：

```text
类型(区域): 具体修改内容 [任务编号]
```

允许类型：

- `feat`：新增功能
- `fix`：缺陷修复
- `content`：内容更新
- `style`：视觉调整
- `refactor`：经授权的重构
- `docs`：文档更新
- `test`：测试更新
- `chore`：工程或协作配置
- `revert`：撤销提交

禁止使用无法识别真实内容的提交名，如 `update`、`修改`、`fix`、`latest`、
`new version` 或 `final`。

首次协作提交固定为：

```text
docs(workflow): establish multi-device collaboration protocol [B-20260728-00]
```

## 正式版本标签

普通任务不创建标签。稳定发布节点使用 `site-v<主版本>.<次版本>.<修订版本>`：

- 大型结构升级：增加主版本；
- 新增完整功能：增加次版本；
- 缺陷修复：增加修订版本。

标签只能指向经过验证的 `main` commit，不移动或覆盖已有标签。

## 推送与回滚

- 推送前必须 fetch 并确认远程没有本地缺失的新提交。
- 只推送完整、已测试、范围正确且不含秘密的 commit。
- 不强制推送，不重写公共历史。
- 异常回滚使用 `git revert <commit>`，回滚提交同样需要测试和部署验证。
