# Motion Library 独立代码生成系统设计

## 目标

将 64 个文字动效从重复嵌入整套样式表的代码块，重建为结构化数据驱动的独立代码包。用户复制任意卡片时，只获得当前动效需要的 HTML、专属 CSS 和可选 JavaScript。

## 数据结构

每个动效保存以下字段：

- `id`：`motion-01` 至 `motion-64`
- `namespace`：`l1-motion-01` 至 `l1-motion-64`
- `name`：英文名称
- `nameZh`：中文名称
- `description`：用途说明
- `technique`：技术说明
- `html`：当前动效的结构
- `css`：基础排版与当前动效规则
- `js`：仅在当前动效确实需要时提供

## 生成结果

每张卡片生成两个代码版本：

1. 独立 HTML：包含完整文档结构、当前动效 HTML、CSS 和可选 JS，可直接保存为 `.html` 预览。
2. 嵌入组件：包含当前动效容器、`<style>` 和可选 `<script>`，用于嵌入现有网页。

代码区通过两个按钮切换版本，复制按钮只复制当前选中的版本。

## 隔离规则

- 所有类名以当前 `namespace` 开头。
- 所有关键帧名称以当前 `namespace` 开头。
- 禁止 `body`、`html`、`:root`、通配符等全局选择器。
- JavaScript 只能从当前命名空间根元素开始查询。
- 单个代码包不得包含其他动效的命名空间或关键帧。

## 生成流程

现有页面仅作为一次性迁移来源。迁移脚本解析每张卡片的预览结构和原代码，从共享样式中提取当前 `tpl-*` 规则及其关键帧，转换为独立命名空间，写入结构化数据。正式生成器从结构化数据重建 64 张卡片代码区。

## 验证

- 数据条目必须为 64 个且 ID 唯一。
- 每项必须同时生成独立 HTML和嵌入组件。
- 每份代码只能包含当前命名空间。
- 每份代码不得包含全局选择器。
- 仅数字计数等确需脚本的效果包含 JavaScript。
- 浏览器验证首张、脚本型卡片和末张卡片的切换与复制内容。
